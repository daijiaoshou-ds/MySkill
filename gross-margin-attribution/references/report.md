# 报告写法

报告面向业务读者，先给答案，再给证据，最后给边界。不要写业务原因，除非用户另外提供了原因数据。

## 建议结构

1. **一句话结论**
   - 本期毛利率从 x% 到 y%，上升 / 下降 z pp；
   - 主维度中谁拉高最多、谁拉低最多。
2. **经营大盘**
   - 收入、成本、毛利、毛利率、成本率；
   - 价格拉力、成本拉力，明确两项可能对冲。
3. **毛利率变动分析（拉力差值）**
   - 正向：累计到 80% 或前 7 大，列出对象、拉力差值、覆盖率；
   - 负向：同样；
   - 每个对象最多 15 张同向订单，写清覆盖率和是否触顶。
4. **毛利率构成分析（拉力水平，只客户 / 产品）**
   - 按所选期间（上期 / 本期）列拉力水平，不是拉力差值；
   - 只讲客户 / 产品，不提地区 / 渠道等其他空维度；
   - 默认全部对象列示、不截断；页面可显式折叠 |拉力| < 0.01pp 的小值，折叠后合计不变；列对象、销售收入、销售成本、毛利率、销售占比、拉力；
   - 说明“本期毛利率 = 上期毛利率 + 本期拉力合计”；上期基期拉力合计为 0；
   - 正负两组各写合计和对象数；不要把它写成“谁导致了变化”。
5. **其他空维度**
   - 地区 / 渠道等维度如果贡献显著，单独一段；
   - 先看 `analysis.json.dimDiagnostics` 的 `recommendation` 和 `weightedMarginDispersion`；
   - `not_recommended` 的维度要标注“单极 / 解释力有限”，不要把它写成主结论；
   - 不要把所有维度都复述一遍。
6. **二维象限**
   - 四象限收入占比变化；
   - 最大迁移路径及成员（`quadrants.paths[].members`）；
   - 说明单条路径变化不等于象限净变化。
7. **数据质量与边界**
   - 负收入 / 负成本 / 负数量 / 零数量，分别引用 `quality.json`；
   - 缺失期间、缺失订单、维度缺失值（`dimDiagnostics[].missingRate`）；
   - 两期口径、6 位小数导出、全精度底稿；
   - 只做数据归因，不解释业务原因。

## 订单口径（先检查再写）

先读 `quality.orderPeriods`。如果 `crossPeriod` 远小于订单总数，必须写“单期订单”，并说明“只能看本期哪张订单贡献了多少拉力，不能看同一张订单前后变化”；禁止写“订单 1847 毛利率上升 / 下降”。只有 `crossPeriod` 足够大时，才允许讨论同一订单的两期变化。

## 措辞

- 用“拉力差值”而不是“增长贡献”；
- 用“价格拉力 / 成本拉力”并说明是相对上期基准，不是价格指数；
- 用“百分点（pp）”描述毛利率变化、拉力、价格拉力、成本拉力、成本率变化，不写“占比下降 20%”；
- `analysis.json` / `data.json` 里的拉力是小数（`0.0191`），不是 `0.0191pp`；写报告时乘以 100 并标成 `+1.91pp`。字段单位见 `analysis.json.units`；
- 收入增长、收入占比、毛利率水平才用 %；
- 说“覆盖正向 83.22%”，不说“解释了 83.22% 的原因”；
- 说“订单 1847 的拉力差值为 +0.46pp”，不说“订单 1847 让毛利率增长了 0.46%”；
- 数据不足时写“当前数据无法判断”，不要补业务故事。

## 可用事实来源

- `work/analysis.json`：报告的主事实源；`units` 明确说明拉力是“占期间收入的比例”；
- `work/data.json`：规范化后的明细，含 `meta.fields` / `fieldIndex` / 逐行 `pull`；
- `work/data.csv`：解码后的平表，6 位小数；
- `work/quality.json`：数据质量，负收入 / 负成本 / 负数量分开；`checks` 是拉力闭合和字典基数，`orderPeriods` 是跨期订单统计，`skippedInvalidRows` / `generatedOrderRows` 是跳过行和行号订单；
- `work/dim_diagnostics.json`：维度分布、缺失率、解释力和推荐级别；
- `work/毛利率归因工作台.html`：交互页面；
- 导出 CSV：6 位小数主明细 / 维度表 / 订单表，以及全精度底稿。

报告里的每个数字都应能在 `analysis.json`、`data.csv` 或导出里找到；不要在报告里重新算一套。

## analysis.json 里有什么

- `totals`：两期收入、成本、毛利率、价格拉力、成本拉力、dGM；
- `conclusion`：主维度正负 top、覆盖率、每个对象的 `orders`；
- `support`：主维度按**本期拉力水平**排序的正向支撑 / 负向拖累，含 `pull0 / pull1 / w0 / w1 / gm0 / gm1`；`net` 应等于 `totals.dGM`；`all` 是全量对象，`positive` / `negative` 只放前 7；订单 `orders.top` 统一最多 15 张；
- `dims`：每个维度的正负对象，含 `k0/k1/q0/q1/p0/c0/p1/c1/gm0/gm1/w0/w1`、`pull0 / pull1`、`shareOfPositive` / `shareOfNegative`、`truncated`、`pullLevels` 和每个对象的 `orders`；小维度（如渠道）有 `all` 全量 delta，客户 / 产品的 `pullLevels.all` 用于全量列示；
- `quadrants.concentration` / `quadrants.paths`：象限占比和迁移路径，路径带 `members` / `memberCount`；
- `orderSummary`：全部订单的正负数量和正负拉力合计；
- `dimDiagnostics`：维度推荐级别、缺失率、两期分布和解释力；主页面顶部也会显示弱维度提示；
- `quality`：数据质量；
- `checks`：逐行校验和维度合计。

订单字段：

- `count` / `sameSignCount`：同向订单数，二者相等；
- `allCount`：该对象全部订单数；不要把它读成 `count`；
- `need`：达到 80% 所需张数；
- `capped`：是否因上限截断；
- `coverage`：已列订单占同向订单合计的比例。
