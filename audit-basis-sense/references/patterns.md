# 审计底稿常见模式库

> 本文列举审计工作中最常见的 Excel 结构模式及其基变换优化方案。
> AI 在分析工作簿时，将实际结构与这些模式匹配，快速给出优化建议。

## 模式 1：同类程序 × 多类别分 sheet

### 识别特征

- 多个 sheet 名称呈现"程序名 + 类别"规律（如"原材料计价测试""半成品计价测试""库存商品计价测试"）
- 列结构 70%+ 相同，仅 1-2 列不同（通常是第一列——明细表名称）
- 每个 sheet 的数据行数相近

### 基变换方案

1. 新增维度列：提取 sheet 名称中的"类别"部分（原材料/半成品/库存商品）
2. 合并为 1 个 sheet，所有行共用同一套列结构
3. 删去原 sheet 特有的"明细表名称"列（已被维度列替代）

### 复杂度变化

| 指标 | 变换前 | 变换后 |
|------|--------|--------|
| Sheet 数 | N | 1 |
| 公式套数 | N | 1 |
| 公式设置 O | O(N) | O(1) |
| 认知判断 O | O(数据行) | O(异常行) |

### 审计场景

存货计价测试、坏账准备测算、固定资产折旧测算、收入确认测试

## 模式 2：同期 × 多期间分 sheet

### 识别特征

- 多个 sheet 名称呈现"内容 + 期间"规律（如"1月费用""2月费用"…"12月费用"）
- 列结构**完全相同**（不仅仅是相似）
- 每个 sheet 行数相近

### 基变换方案

1. 新增维度列："月份"或"期间"
2. 合并为 1 个 sheet（如"年度费用汇总"）
3. 筛选/透视表分月查看

### 复杂度变化

| 指标 | 变换前 | 变换后 |
|------|--------|--------|
| Sheet 数 | 12 | 1 |
| 公式套数 | 12 | 1 |
| 跨期汇总 | 需跨 sheet 引用 | 一个透视表搞定 |

### 审计场景

月度费用分析、月度收入分析、月度往来款变动、12 个月银行余额调节表

---

## 模式 3：同模板 × 多实体分 sheet

### 识别特征

- 多个 sheet 名称呈现"模板 + 实体"规律（如"销售部费用""研发部费用""管理部费用"）
- 列结构**完全相同**
- 每个 sheet 行数可能不同

### 基变换方案

1. 新增维度列："部门"/"公司"/"主体"
2. 合并为 1 个 sheet
3. 统一公式框架，透视表分组查看

### 复杂度变化

| 指标 | 变换前 | 变换后 |
|------|--------|--------|
| Sheet 数 | N | 1 |
| 公式套数 | N | 1 |
| 跨实体比较 | 需手动汇总 | 透视表一键 |

### 审计场景

部门费用分摊、多子公司往来核对、多主体收入确认

---

## 模式 4：序时账/明细表（单 sheet 大海量行）

### 识别特征

- 仅 1 个 sheet，但行数极大（万级～十万级）
- 列结构标准（记账日期、凭证号、摘要、科目、借方金额、贷方金额）
- 信息熵集中且混乱——所有向量在同一个 4-5 维空间中密集分布

### 这不是基变换场景

序时账已经是**最小基结构**——它只有 1 个 sheet，已经是最简空间。但它的问题在于**认知判断的 O(N)**。

### 优化策略（非基变换）

1. **摘要归类**：新增"费用类型"维度列，用公式/规则自动分类 → A_cog → A_ui
2. **异常标记**：用条件格式/公式自动标记异常行 → 认知判断从 O(N) 降到 O(异常数)
3. **抽样检查**：无法全部核对时，科学抽样 → O(N) → O(K)，K = 抽样数

---

## 模式 5：完全异构 sheet（不可合并）

### 识别特征

- 多个 sheet 列结构**完全不同**（重叠率 < 50%）
- 语义上不属于同一类底稿
- 例如：sheet1=序时账、sheet2=科目余额表、sheet3=固定资产清单

### 处理

**不做基变换**。这是自然的向量空间划分——每个 sheet 属于它自己的子空间，不应强行合并。

AI 应回复："当前工作簿中的 sheet 结构差异较大，各自属于不同类型的底稿，不适合合并。如果某个 sheet 内部有优化空间，请具体描述。"

---

```
        │
        ▼
┌─ 多个 sheet 列结构相同/相似？─── 否 ──→ 模式 4 或模式 5
│       │
│      是
│       │
│       ▼
│  ┌─ 差异仅在第一列（名称类）？─── 是 ──→ 模式 1（同类程序多类别）
│  │
│  │  否
│  │
│  │  ▼
│  ├─ 差异在"期间"维度？────────── 是 ──→ 模式 2（同期多期间）
│  │
│  │  否
│  │
│  │  ▼
│  └─ 差异在"实体"维度？────────── 是 ──→ 模式 3（同模板多实体）
│
▼
提出基变换方案 + 估算复杂度变化
```
